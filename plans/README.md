## Deferred findings (run 2, vetted but not planned)

Higher-value first; all evidence verified against `9244f32`:

- **Mouse hook cross-locking**: `ReadPressedModifiers` takes the keyboard
  service lock 5× per wheel/button event, nested inside the mouse gate
  (`NativeMouseHotkeyHook.cs:298-312` + `NativeKeyboardEventService.IsKeyDown:116-134`).
  Fix: publish modifier state + hook-installed flag as volatile fields updated
  under the keyboard lock; fast-path read without locking. MED risk.
- **Audio endpoint COM churn**: `NativeAudioDeviceController.WithDevice`
  creates a new `MMDeviceEnumerator` + activates `IAudioEndpointVolume` +
  opens the property store per script call (`NativeAudioDeviceController.cs:185-208`);
  milliseconds per `hs.audiodevice.*` call. Fix: cache endpoints keyed by
  device id, invalidate on device change (or coarse TTL).
- **ScriptArgumentReader re-enumerates V8 property names per lookup**
  (`ScriptArgumentReader.cs:48` — `PropertyNames.ToHashSet()` per
  `GetPropertyValue` call, ~10× per options parse). Fix: try-`GetProperty`-
  per-alias first, fall back to enumeration.
- **Unbounded scroll-callback queueing**: one closure + `SynchronizationContext.Post`
  per subscription per wheel event with no backpressure
  (`MouseScrollWatchDispatcher.cs:70-79,113-133`); fast scrolling with a slow
  JS callback grows the dispatcher backlog without bound. Fix: coalesce
  pending notches per subscription or drain via one scheduled work item.
  MED risk (aggregation changes semantics — may need an opt-in).
- **hs.timer architecture**: one `DispatcherTimer` per timer, all ticks on
  the UI dispatcher, minimum interval 1ms that DispatcherTimer cannot honor
  (`DispatcherScriptTimerService.cs:43-52`, `TimerScriptApi` min 1). One slow
  timer callback stalls all timers, toasts, and dispatcher-scheduled script
  callbacks. Fix: dedicated scheduler thread that still takes the script
  gate, or document/round realistic resolutions. MED risk (threading
  contract scripts implicitly rely on).
- **Focus-watch snapshot cost**: `NativeWindowService.HandleWinEvent` builds
  a full snapshot incl. `Process.GetProcessById(...).ProcessName` per
  foreground change and copies the watches array per event
  (`NativeWindowService.cs:219-248, 360-379`). Fix: PID→name cache + array
  snapshot pattern (same as plan 005 step 1).
- **Toast render cost**: quality 42px `DropShadowEffect` re-renders every
  frame while the loader spin animates inside the shadowed border, and the
  exit animation animates `BlurEffect.Radius` (`ToastWindow.cs:53,288-301`,
  `ToastExitAnimator.cs:63-69`). Fix: `BitmapCache` on the pill content or
  animate opacity only. MED risk (visual fidelity at fractional DPI).
- **Per-toast diagnostic logging**: 3 Info lines + `FormatTextForLog`
  (4 chained `Replace`, twice) per toast show
  (`ToastPresenter.cs:79,84,157-161,290-297`).
- **MapVirtualKey per injected event** (`KeyboardInputSender.cs:195-205`):
  memoize per-VK scancodes, invalidate on layout change. Small.
- **Startup prewarm ordering**: toast prewarm runs serially before the
  config reload is queued (`AppController.cs:154-160`); queue reload first,
  prewarm at `DispatcherPriority.Background`.
- **Log retention**: runtime-logs/config-logs grow unbounded, one file per
  launch/reload; add N-day cleanup on a background thread at startup.

## Findings Considered And Rejected

- Run 1: see git history of this file for run-1 rejections (GitHub Actions
  versions, `hs.keyboard.watch` undefined returns, previous-instance cleanup
  breadth, NuGet audit).
- Hook thread re-creation on empty→active watch transitions
  (`EnsureHookInstalled` news a thread per re-install): deliberate
  power-saving design; typical configs do not toggle the last watcher on/off
  at frequency. Not worth the shutdown-handling complexity.
- `Screen.FromPoint` caching for `hs.mouse.getCurrentScreen`: sub-ms WinForms
  call, LOW confidence the internal enumeration is even measurable here.
- Blocking-watch fail-open gate (30ms), scroll callbacks scheduled off the
  hook thread, 8ms blocking-callback soft budget, fresh V8 engine per reload,
  callbacks serialized under one gate: all deliberate, documented designs
  (README) — their throughput consequences are accepted trade-offs.
- `SystemHttpService` (shared static HttpClient), clipboard change notifier
  (message-based, no polling), input senders (stackalloc, no per-tap logs),
  `NativeMediaController` (SendInput per user command), CLI startup (V8 only
  for lint): audited clean.
